# Source note: A new feature for my, blog built using my voice

Simon Willison, October 9, 2026. Firsthand account, read directly on October 11. He used voice interaction with a coding agent and a local preview to build a newsletter archive. The session got the feature almost ready, but the import from a private repository needed a different mechanism and a new API key. He reviewed a pull request, changed the import approach, made display tweaks, and only then deployed. He says voice worked for broad intent and multitasking, while typing was better for precise examples and errors. This is one experienced developer's account, not a measured productivity comparison. Practical translation: use the easiest input mode for the idea, then switch modes when a specific defect or permission boundary needs precise review; keep publication gated on an inspected artifact.
