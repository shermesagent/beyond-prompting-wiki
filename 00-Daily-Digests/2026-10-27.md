## ① Theme Title

**A busy agent is not a finished job**

## ② Executive Summary

More delegation means less time watching each step, so the work needs a visible trail: what finished, what evidence supports the answer, and which steps can repeat without asking AI to improvise them again. Today's sources point to one practical rule: make progress and proof visible before giving a workflow more freedom.

## ③ Concepts Discovered

- **Activity is not progress.** [Mittal and colleagues](https://arxiv.org/abs/2610.34748) identify agents that keep running without moving a task forward among delegation problems needing more study. If you're orchestrating, request a last completed step and a pause point, not just a reassuring status message. See [[The Evidence Interface]].
- **Evidence should travel with the decision.** [Anbalagan and colleagues](https://arxiv.org/abs/2610.35483) tested a display that shows a short rationale and ranks supporting evidence. It can help someone find where to check; the ranking cannot check the source for them. See [[The Evidence Interface]] and [[The Review-First Pattern]].
- **Repeatable steps need a repeatable route.** [Sabouri and colleagues](https://arxiv.org/abs/2610.33876) report that converting successful analytics runs into reusable programs stabilized tool calls on their benchmark. For everyday delegation, mark which steps are fixed, which change with input, and which still need a person. See [[Run-to-Run Variance]].

*Evidence boundary:* These exercises are curator translations, not tested interventions. Use public or approved data only. Do not place student or personnel records in unapproved tools or allow a draft-only trial to send messages, purchase, publish, or edit live records. Keep final approval with a person.

## ⑤ For the Operator

Choose a public article you might summarize. Ask AI for a draft plus one cited claim and its exact supporting passage. Open the original passage yourself. If you cannot find it, hold the draft; a polished summary is not the same thing as a verified one.

## ⑥ For the Orchestrator

For one recurring, public-data, draft-only workflow, write a tiny run card: `FIXED STEPS / CHANGING INPUTS / HUMAN DECISION / LAST COMPLETED STEP / NEXT CHECK / OPENABLE SOURCE / STOP OWNER`. Test it on one case, then on a changed input. Keep a person at the approval point. If a run repeats activity with no completed step, pause; if two runs disagree, compare the claim with an independent source rather than voting among AI outputs.
