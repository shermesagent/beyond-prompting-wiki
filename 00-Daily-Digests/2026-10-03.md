## ① Theme Title

**More Freedom Requires a Real Stop, Not Just a Permission Setting**

## ② Executive Summary

Granting an agent more room to work can make a workflow feel smoother, but permission to act is not the same as a way to check, interrupt and recover. A provider's observation of real agent use, a voluntary government playbook and older interaction-design research together suggest a small test: can you name the owner, the evidence, the pause point and the recovery step before the run starts?

## ③ Concepts Discovered

- **Permission versus stop path:** [Anthropic's analysis](https://www.anthropic.com/research/measuring-agent-autonomy) found experienced Claude Code users more likely to auto-approve *and* interrupt. Those are observed behavior changes in one product, not proof that extra autonomy is safe. For the move from operator to orchestrator, try giving an agent a low-stakes draft while keeping a working interrupt and no send permission. See [[Autonomy]].
- **Oversight as a recoverable interaction:** [Microsoft Research's 2019 guidelines](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/) were tested with design practitioners on AI products, not with today's long-running agents. They offer a useful prompt for design: can a person see, correct and recover from an AI mistake? Try the four-line check in [[Oversight]].
- **Governance in four verbs:** [NIST's voluntary playbook](https://www.nist.gov/itl/ai-risk-management-framework/ai-rmf-playbook) organizes risk work as Govern, Map, Measure and Manage. Translated into everyday delegation: name an owner, identify who is affected, decide what evidence to check, and specify what happens if the check fails. This is a local exercise, **not** NIST certification. See [[Oversight]] and [[Human in the Loop]].

## ⑤ For the Operator

Take a public, non-sensitive document and ask AI for a **draft only**. Before you accept it, identify one source you can check without asking the same AI and one action it must not take (such as sending). If you spot an error, correct it in the draft and note how you found it. You're practicing oversight without giving up the steering wheel.

## ⑥ For the Orchestrator

Pilot one approved, low-risk workflow with four written fields: `OWNER`, `INDEPENDENT EVIDENCE`, `PAUSE BEFORE EXTERNAL ACTION`, `RECOVERY`. Run a harmless wrong-input test and verify that the named person can actually stop it. If stopping or recovery fails, return to draft-only mode; do not connect live student records just to test the idea. [[Autonomy]] names the permission dial; [[Oversight]] makes the stop path concrete.
